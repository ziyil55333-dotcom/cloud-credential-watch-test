# 项目方回复

已读到 [zhoumouai 的进度回执](zhoumouai-blind-review-2026-11-26.md)。本轮五个公开入口的基线重新扫描均为零告警，MediaWiki 本轮地址待启动。当前正式投放为 0/144，待评审人确认样本和封存。

## 封存前要做的事

- 评审人本人核对合成样本、正负位置和预期标签。四张登记表、样本值与标签在本机准备。生成封存记录后，在原回执追加封存时间、`manifest_sha256` 和可同步操作的时间段（北京时间）。
- **OCI** 在本机先把计划投放的镜像打包，核对样本所在层。标签的 `path` 使用实际压缩层摘要和包内路径，格式为 `sha256:摘要:路径`。后续推送同一制品，保留原层摘要。实际发布回执登记的是镜像清单摘要。
- **APK** 先确认 24 版的相对包内路径与计划一致。用实际 APK 或待构建的资源目录核对，例如 `assets/acceptance/probe-01.env`。封存登记的是包内路径，实际发布时再回填版本号和 APK 的 SHA-256。

## 发布分工

| 入口 | 操作与回执 |
| --- | --- |
| GitHub | 评审人可在 `codex/blind-github` 发布。观察就绪后逐次提交，回填完整 SHA。 |
| Gitee | 项目方协助在 `codex/blind-gitee` 逐次发布，回填完整 SHA 和发布时间。 |
| MediaWiki | 项目方协调启动 `codex/blind-wiki` 现有 Actions 作业，评审人接入本轮 `wiki-asset.json` 并确认观察就绪。作业留下 8 分钟接入时间，结束后用本轮制品回填修订号。 |
| 文章 | 项目方协助更新测试栏目和 RSS，回填条目标识、正文摘要和发布时间。 |
| OCI | 项目方协助向 `blind-eval` 推送已经核对层摘要的制品，回填镜像清单摘要和发布时间。 |
| APK | 项目方协助构建或校验本轮测试 APK，并更新 `codex-blind-apk` 发布索引，回填版本、制品摘要和发布时间。 |

用本批次回执协调时间。观察就绪后，如需代发，按交接站说明提交可公开的合成投放文件与计划编号。每次保留上一版的扫描结果和失败记录再推进。标准答案和封存原件在首轮扫描结束后按交接说明提交。
