# 独立评审回执填写方式

在本目录新增一份 Markdown，文件名包含执行账号、任务编号和日期，提交至 `codex/review-handoff`。用这份回执记录后续进度和项目方回复。

- **任务编号**填写 `extension-review`、`blind-preflight` 或 `blind-review`。
- **执行账号和日期**填写实际账号与记录日期。状态填写进行中、待确认、已完成或受阻。
- **盲测封存**在首次扫描和投放前登记 `seal.json` 中的 `manifest_sha256` 与封存时间。整轮首次扫描结束后公开预期标签与封存原件。
- **代发请求**写明渠道、批次、计划编号、目标测试入口和所需操作。发布方回填实际版本标识与发布时间。需要交换投放文件时，在本轮观察程序就绪后向交接分支提交可公开的合成文件，记录提交链接。采集配置指向已登记的测试入口。
- **评审结果**记录六个入口的实际发布数、通过数、失败数和未执行数，附上结果目录链接。项目方核验后在本目录提交核验结果。

## 盲测复核文件

在 `results/blind-review/` 下用批次编号建目录。整轮首次扫描结束后，由评审人确认文件可以公开，再提交以下记录。

- `manifest.json`、`seal.json`、`receipts.json`、`alerts.json` 为审核输入，按首次执行原样提交。
- `events.json` 和 `sources.csv`、`releases.csv`、`receipts.csv`、`labels.csv` 用来复核过程和原始登记表，提交经检查可公开的文件。登记表里使用公开测试资产 ID、资产内相对路径及评审编号或公开 GitHub 账号。回执可附文件的 SHA-256，供取回时核对。

本仓库和提交历史公开可读。`.state`、账号凭据、登录信息、本机绝对路径、真实样本或其他非公开材料留在评审人本机。如果某份审核输入无法公开，保留原件并在回执写明具体缺项，封存文件的 SHA-256 以原件为准。
